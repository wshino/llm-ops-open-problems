# [problem] subscription 型 LLM の limit 逼迫を予測して routing を切り替えられない

## 困っていること

定額 subscription の LLM (Claude 等) には weekly や数時間単位の利用上限があり、上限に当たってから慌ててローカルモデルや別サービスに切り替える、を繰り返しています。使用量の推移から逼迫を予測して、事前にタスクの routing (高いモデルは判断だけ、要約などは安いモデルへ) を変えたいのですが、そもそも使用量をプログラムから取る方法の時点で手探りです。

## 環境

- Claude Code (subscription)、Codex CLI、ローカル LLM の併用
- タスク種別ごとに委譲先を決める routing ルールを手動運用

## 試したこと

- 使用量の手動確認と、逼迫してからの手動切り替え
- タスク種別ごとの routing ルール整備。ルール自体は機能するが、切り替えタイミングが常に後手になる

## どんな解決なら嬉しいか

使用量の取得と逼迫予測の実装例。しきい値で routing を自動で切り替えている運用事例や、subscription 側の使用量を観測する現実的な方法の共有でも嬉しいです。
