# [problem] 複数の agent runner の完了通知を一元監視できない

## 困っていること

Claude Code、Codex CLI、ローカル LLM 駆動の agent を並走させていると、どれが完了したか、どれが permission 入力待ちで止まっているかを見に行く手段がツールごとにバラバラです。通知の取りこぼしが起きて、気づいたら入力待ちのまま 1 時間止まっていた、が何度も起きています。並走数が増えるほど「全部を見て回るコスト」が自動化の節約分を食い潰していきます。

## 環境

- macOS (Apple Silicon)
- Claude Code、Codex CLI、orchestrator 系ツール (paseo 等) の併用
- git worktree で作業ツリーを分けて並走させる運用

## 試したこと

- 各ツールの通知設定。ツール内では機能するが、runner をまたいだ一覧にならない
- tmux でペインを並べて目視。数が増えると破綻する
- orchestrator の agent 一覧 API をポーリング。worktree 内で動く agent が既定のフィルタから漏れて、一覧に出てこないケースがあった

## どんな解決なら嬉しいか

runner をまたいで「実行中 / 入力待ち / 完了 / 異常停止」を 1 か所で見られる仕組み。既存 OSS の組み合わせでこう運用している、という事例の共有でも十分嬉しいです。
