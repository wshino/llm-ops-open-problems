# [problem] 安いモデルに委譲したタスクの「本質的な見落とし」を検知できない

## 困っていること

コスト削減のため、要約やコードレビューをローカルの安いモデルに委譲しています。表面上はそれらしい出力が返ってくるのですが、セキュリティ上の問題や設計の穴といった「一番拾ってほしい指摘」を見落としていても、出力からはそれが分かりません。結局高いモデルで抜き取り検証することになり、どこまで委譲してよいかの境界を経験則でしか引けていません。

## 環境

- ローカル LLM (GLM 系、Kimi 系の量子化モデル) を review / 要約の下請けに使う構成
- 上位モデル (Claude 等) を最終判断に残す 2 段構成

## 試したこと

- 高いモデルによる抜き取りの二重チェック。コストが戻ってしまい本末転倒気味
- レビュー観点の checklist を prompt に埋め込む。checklist にない種類の穴は素通りする

## どんな解決なら嬉しいか

委譲先モデルの見落とし率を定量化する評価方法。既知の欠陥を仕込んだテストセットでの計測手法や、「この種のタスクは委譲可 / 不可」の判断基準を実測で共有してもらえると嬉しいです。
