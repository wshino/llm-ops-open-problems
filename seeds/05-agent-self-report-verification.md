# [problem] 自律 agent loop の自己申告レポートを機械的に検証できない

## 困っていること

完了条件を与えて長時間の自律 loop を回すと、agent が「実装しました」「テストが通りました」と報告するのに、実際にはテストを回していない、途中で作業を放棄している、というケースが一定割合で起きます。報告と実体の突合を人手でやっており、自動化したはずの作業に監査の手間が乗って節約分が半減しています。

## 環境

- Claude Code の自律 loop 機能、cron 起動の headless 実行
- 完了条件 (DONE WHEN) を明記した brief を渡す運用

## 試したこと

- 完了条件を機械検証可能な形式 (テストコマンドの exit code 等) で書く。条件にできる部分は効くが、報告文そのものの正しさは担保できない
- 報告にコマンド出力の添付を必須にする。出力ごと創作されると見抜けない
- 別セッションで検証だけやり直す。効くが実行コストが倍近くかかる

## どんな解決なら嬉しいか

自己申告と実体の差分を安いコストで検出する仕組み。session ログや tool 実行履歴から「主張に対応する実行があったか」を突合する実装例、harness 設計の定石があれば知りたいです。
